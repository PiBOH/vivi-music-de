COME FUNZIONA
  - All'inizio di addCurrentTo, deletePlaylists, renamePlaylist e della
    creazione di una playlist viene chiamato forgetUndo(): una nuova azione
    sostituisce il token precedente (slot singolo).
  - Undo di una rinomina: se rename fallisce, il token NON viene cancellato;
    il messaggio riporta l'errore e Undo si puo' ripremere.
  - Undo di un'eliminazione: restore() ricrea nome e tracce. Se alcune
    playlist falliscono, il token persistito contiene solo i loro snapshot;
    le riuscite non vengono ricreate una seconda volta.
  - Undo di un'aggiunta: removeSong() viene chiamato solo per le playlist in
    addedPlaylistIds. Se alcune rimozioni falliscono, il token persistito
    contiene solo quei loro id.
  - Se falliscono tutte, il token resta invariato (in memoria e su disco) e
    si puo' ritentare.
  - La barra e' per account; createdAt non fa scadere nulla.

  3. Apri il gruppo "Missing song files".
  4. Premi "Relink automatically".

COME FUNZIONA
  1. Considera solo i brani locali mancanti: File(path).isFile falso, con
     navidromeId/jellyfinId nulli e path non ytmusic:// o http(s).
  2. Cammina le cartelle musicali configurate, saltando quelle escluse.
     Estensioni considerate: mp3, flac, ogg, opus, m4a, wav, aac, wma.
  3. Prima prova il nome file esatto, case-insensitive.
  4. Se non ottiene ESATTAMENTE un match, prova il nome normalizzato del file:
     minuscole, accenti rimossi, solo lettere/numeri. Il nome normalizzato
     deve CONTENERE il titolo normalizzato e, se l'artista non e' vuoto, anche
     l'artista normalizzato. Non e' un confronto di uguaglianza.
  5. Scarta i file gia' puntati da un brano valido e quelli gia' usati in
     questa passata.
  6. Offre il brano solo se resta esattamente un candidato; due file ambigui
     restano manuali.
  7. relinkSongs scrive in un solo update. Salta un brano il cui vecchio path
     e' tornato valido, il cui nuovo file e' sparito dopo l'anteprima, o che
     compare due volte nei candidati.
  8. Ogni brano mantiene id, like e riferimenti nelle playlist: cambia solo
     path (e contentUriString).

COSA FA
  Una scansione completa non cancella i brani di una radice che non e'

    suspend fun scanDirectories(...) =
        withContext(ioDispatcher) { scanMutex.withLock { scanDirectoriesImpl(...) } }
    private suspend fun scanDirectoriesImpl(...)
    val scannedDirectories = mutableListOf<String>()
    val failedDirectories = mutableListOf<String>()
    var walkFailed
    override fun preVisitDirectory(...)   // eccezione -> walkFailed = true
    override fun visitFileFailed(...)     // walkFailed = true
    override fun postVisitDirectory(...)  // exc != null -> walkFailed = true

        else scannedDirectories.add(rootDirAbs)
    if (pruneMissing && scannedDirectories.isNotEmpty())
        musicDao.deleteSongsNotInPaths(allDiscoveredPaths, scannedDirectories)

        addedOrUpdated,
        durationMs,

COME FUNZIONA
  - scanMutex serializza le scansioni complete: la seconda aspetta la prima.
    scanFiles (il watcher) non prende il mutex.
  - Per ogni radice configurata:
      * se non esiste, non e' una directory o e' esclusa, viene saltata e NON
        entra ne' in scannedDirectories ne' in failedDirectories;
      * se viene camminata, ogni errore di visita (visitFileFailed, eccezione
        in preVisitDirectory, postVisitDirectory con exc) marca walkFailed;
      * se walkFailed, la radice finisce in failedDirectories e NON in
        scannedDirectories.
  - deleteSongsNotInPaths pota solo dentro le radici di scannedDirectories:
    i brani di una radice fallita restano, anche se non sono stati visti in
    questa passata.
  - Una radice che non esiste non aumenta skippedDirectories: i suoi brani
    restano, ma il conteggio resta 0. skippedDirectories conta solo le radici
    che esistevano e sono fallite durante la camminata.
  - pruned e' true solo se pruneMissing era richiesto e almeno una radice e'
    stata camminata completamente. Non significa che TUTTE le radici siano
    state lette.
  - CancellationException viene rilanciata: non diventa ScanProgress.Error.
